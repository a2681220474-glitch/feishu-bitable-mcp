# 使用方式与授权边界

## 当前能用的开源部署方式

每位使用者自行部署，使用自己的飞书应用和数据。代码按 MIT 许可证开放，项目维护者不参与使用者的账号许可或数据授权。

一次性配置包括：

1. 在自己的飞书开发者后台创建或复用企业自建应用，把 App ID、App Secret 放入自己的 `.env`。
2. 开通所需 API 权限，并按所在企业流程发布/批准应用。
3. 给该应用目标 Base 的读取权限；人的访问权不会自动传给应用身份。
4. 安装并启动 MCP，配置 HTTPS 地址和适合客户端的访问鉴权。ChatGPT 网页端必须能访问这个服务，不能只连接本机未公开的 localhost。
5. 在 ChatGPT 添加该实例的 `/mcp` 地址，完成鉴权后，把标准飞书 Base URL 交给工具。

详见 [配置与自检](setup.md)。开发分支中的可选 MCP 登录方式只控制谁能调用该实例，读取范围仍由其飞书应用身份决定；真实 ChatGPT 浏览器接入尚待验收。

## 下一阶段目标：飞书个人授权

期望使用流程：部署者一次配置飞书应用与服务 → 使用者在 ChatGPT 添加 MCP → 跳转飞书登录并同意读取权限 → 以该使用者的身份读取其有权访问的表格。

此流程尚未实现。实施时应优先复用飞书官方授权机制，处理用户令牌刷新、加密存储、撤销、会话隔离，并验证 MCP 客户端授权协议的兼容性。不能只把应用 token 换成某个固定人的 token，也不能以一位部署者的个人权限代替所有访问者的权限。

用户身份的有效范围受 API 支持、应用已获权限、用户同意和企业/资源策略共同约束，不能承诺覆盖所有网页可见内容。用户可以读取别人分享给自己的表格，但仍须满足对应 API 和资源权限。

## 自行部署与托管服务

自行部署需要使用者准备自己的应用和运行环境；这些步骤可以通过初始化向导简化，但不能把维护者的私有凭据打包进开源仓库。

若希望普通使用者只做“在 ChatGPT 添加地址、飞书登录同意”，就需要有一个运营者提前托管服务并配置应用。运营者还要解决用户隔离、凭证保管、企业安装及跨企业应用可用性。这属于额外的服务交付，公开代码本身不等于已经提供了托管服务。

当前项目处理飞书多维表格；普通飞书云文档正文读取仍不在现有工具范围内。

参考：[飞书官方 CLI 的配置与用户授权](https://github.com/larksuite/cli)、[OpenAI MCP Authentication](https://developers.openai.com/plugins/build/auth)。
