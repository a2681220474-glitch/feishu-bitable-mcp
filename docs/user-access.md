# 使用方式与授权边界

每位部署者使用自己的飞书应用、运行环境和账号，无需项目维护者批准，也无需把 Secret 交给维护者。

## 推荐：飞书本人授权

一次配置应用与 HTTPS 服务 → ChatGPT 添加 `/mcp` 并选择 OAuth → 飞书登录并同意读取 → 以该使用者身份读取资源。

`FEISHU_AUTH_MODE=user` 使用 FastMCP OAuth 代理，处理客户端注册、同意、PKCE、加密状态和刷新。MCP 客户端获得的凭证与飞书原始访问令牌分开，原始访问/刷新令牌不返回给客户端。

每次请求从认证上下文取得其用户凭证，不用一个全局个人 token 代替所有访问者。未登录、过期或撤销时不回退到应用身份。刷新可用时续期，否则在 ChatGPT 重新连接并登录；用户可在飞书撤销授权。

有效范围受用户自身权限、用户同意、应用 API 权限和企业策略约束，不能承诺覆盖所有网页内容。用户模式只注册读取工具。

## 兼容：应用身份

`FEISHU_AUTH_MODE=app` 保留企业自建应用模式。应用需获得目标资源权限；人的访问权不会自动传给应用。远程实例需配置适合客户端的 MCP 鉴权。可选记录创建仅在该模式按既有保护开启。

## 运行位置

ChatGPT 网页端必须能从其网络访问服务。自己的电脑加 HTTPS 隧道，或服务器上的反向代理均可；应转发整个服务。飞书开发者后台不托管本项目的 Python 进程。

不需要为本项目到 OpenAI Platform 创建 API Key 或购买 API 额度。本项目不调用 OpenAI API；需要自己 ChatGPT 账号中可用的自定义 MCP 功能。

代码开源不等于提供公共托管服务。共享实例的运营者需负责隔离、凭证和企业应用可用范围；不要分享自己的 `.env` 或 OAuth 状态目录。

## 验证状态

开发分支已经通过模拟的完整链路：注册、同意、PKCE、授权码交换、MCP 读取、刷新、撤销后拒绝，以及并发用户隔离。真实飞书应用和 ChatGPT 浏览器验收仍待进行；Mock 不证明某租户权限或所有视图行为。
